# 扩展自动检查更新

扩展页的“扩展更新检查”提供设备侧开关、1–168 小时检查间隔和“立即检查所有扩展更新”。默认关闭，默认间隔 24 小时。开启后应用运行期间每分钟判断是否到达检查时间；不会启动后台常驻程序，应用退出期间不检查。配置保存在设备 `_local/extensions/update-checks.json`，不进入 Notebook 归档或知识备份。

自动检查只访问已安装、全局启用、发布者仍受信任且具有公开 HTTPS 更新地址的签名扩展。检查不要求打开 Notebook、不读取其笔记，也不会把 Notebook 内容、云凭据或系统密钥发送给扩展来源。开启开关即授权按此范围定时访问这些地址；远端能看到访问时间与网络 IP。目录本身不被自动刷新。

## 提示、审核与安装

检查复用 [远程分发](EXTENSION-DISTRIBUTION.md) 的 HTTPS/公网地址、大小、签名、原公钥、扩展身份和版本检查。发现新版仅保存有限的版本状态，不保存待安装包、不创建安装审核快照，也不改变现有安装或 Notebook 授权。

扩展页显示“发现新版，等待审核”，点击“审核扩展更新”才重新下载进入现有签名包审核。用户确认安装后清除该扩展旧的 Notebook 授权；再次使用须重新授权。相同内容显示当前已是最新版本。签名错误、版本回退、同版本内容替换或网络故障记录为检查失败，不安装、不覆盖正文。

检查结果按当前安装内容校验值和来源地址过滤；卸载、安装内容改变、全局停用或撤销发布者信任后，旧提示不继续显示。设备状态在扩展页约每 5 秒刷新，该刷新只访问本地后端，不触发网络检查。

## 间隔与取消

检查时间从上次尝试开始计时，成功或失败均按配置间隔再试，避免离线时每分钟重试。重启应用保留上次尝试；更改设置使下一次自动检查重新到期。系统时钟回退时允许重新检查。

只有一轮检查运行，扩展按顺序检查，与目录/手动下载共享最多 2 项网络任务，每次下载保持 20 秒 deadline。最多检查 64 个安装来源；大量连续超时可能使整轮检查耗时较长，但不会占用知识库写入队列。既有设备结果保留到整轮完成或新结果提交；失败后可在页内立即重试。

“取消更新检查”、改变配置、关闭自动检查或退出应用都会终止正在运行的检查。配置修订和后端会话令牌防止取消或配置改变后的旧结果写回。取消自动检查不会取消独立的用户目录/包下载。

当前实现是自动检查与人工审核安装，不是静默自动安装。中央市场审核运营、通用第三方 React/JS 宿主及独立应用自动升级仍不属于本功能。

## 验证记录（2026-10-03）

完整回归 134 项通过，新增更新检查专项 5 项覆盖默认关闭与持久化、时间间隔、显式检查、签名失败、不重叠执行、取消与关闭、配置改变后的旧结果拒绝，以及撤销信任或全局停用后的来源和提示过滤。严格 TypeScript 编译、SDK 离线消费与 Linux 打包通过。

生产构建与 Linux 打包应用各通过 15 项编辑器/扩展界面检查、13 次无障碍扫描，违规为零。更新场景等待实际应用的 60 秒调度器，验证发现新版保留旧安装和授权，审核确认后需要重新授权。网络响应在真实 Storage utility process 中受控模拟；未部署外部扩展服务，不代表真实公网托管验收。报告见 `test-results/editor-ecosystem*.json`，截图见 `docs/screenshots/editor/automatic-update-check.png`。
