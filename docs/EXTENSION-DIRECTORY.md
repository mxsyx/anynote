# 扩展目录浏览

扩展页支持保存最多 8 个公开 HTTPS 目录。填写名称和目录地址，点击“保存扩展目录”，再点击该目录的“刷新目录”获取条目。可按名称、扩展 ID 和描述搜索，选择“下载目录扩展并审核”进入现有签名审核、发布者信任与 Notebook 授权流程。

目录清单是远端的来源声明，没有独立的发布者认证；它不能自动信任某把公钥或授予任何权限。实际包必须通过 Ed25519 验签，且扩展 ID、名称、版本、运行时、权限、内容 SHA-256、公钥指纹和目录提供的描述均与清单一致。仍需通过独立渠道核对发布者公钥指纹。

## 生成与托管

先按 [签名文档](EXTENSION-SIGNING.md) 制作签名包，再生成目录：

```sh
pnpm run extension:package directory '我的阅读扩展' /tmp/extensions.json /tmp/reading-transform.signed.json https://example.com/reading-transform.signed.json
```

每个包文件后跟对应的公开 HTTPS 下载地址；可追加更多包与地址。工具验证各包签名和 manifest，从实际包生成元数据、内容校验值与公钥指纹，拒绝重复扩展 ID、无效地址和覆盖已有输出。生成过程不联网，也不读取私钥。

将生成的 `extensions.json` 与签名包托管在自己的 HTTPS 服务，再把目录地址加入桌面。更新目录时重新生成并替换托管文件；应用仅在用户点击刷新时获取新清单。此实现未部署中央服务器或发布任何外部文件。

## 目录协议

格式为 `anynote.extension-directory.v1`，包含 `name` 和最多 100 项 `entries`。各项包含：

| 字段                               | 用途                                                                                                     |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `id`、`name`、`version`、`runtime` | 扩展标识、名称、`0.1.N` 版本和支持的运行时                                                               |
| `description`                      | 可选描述                                                                                                 |
| `permissions`                      | 声明的笔记读写权限，顺序须与实际包一致                                                                   |
| `url`                              | 公开 HTTPS 签名包地址                                                                                    |
| `checksum`                         | 通过现有严格 manifest schema 解析后，`JSON.stringify` 内容的 SHA-256；沿用安装目录中的 manifest 校验口径 |
| `fingerprint`                      | Ed25519 公钥 SPKI DER 的 SHA-256                                                                         |

不接受重复 ID 或额外字段。SDK 提供 `ExtensionDirectory`、`ExtensionDirectoryEntry` 和 `SavedExtensionDirectory` 可移植类型。清单不包含可执行入口、远程图标或网页脚本。

## 快照、联网和数据边界

目录配置存在设备的 `_local/extensions/directories.json`，不进入 Notebook 归档或知识备份。保存、列出和移除配置不联网；应用启动与 Notebook 切换不自动刷新目录。

刷新后后端保存一份 10 分钟有效的目录快照，每个已配置目录最多一份。选择扩展时使用快照内的包地址和校验信息，Renderer 无法提供替代元数据。再次刷新、修改配置或移除目录会使旧选择失效。目录远端内容在浏览期间改变，不会改变已展示快照的下载目标；实际包改变导致校验不符时要求刷新。

目录下载最多 256KiB，与签名包下载共享 20 秒 deadline、2 项并发、公网 DNS/IP 检查、HTTPS 不降级和 3 次重定向上限。网络阶段释放知识库写入队列，支持取消与服务关闭终止。条目下载仍采用 160KiB 包预算和原有安装审核快照。非法编码、畸形元数据、私网目标和超大响应均被拒绝。

移除目录会删除其浏览快照，不卸载已安装扩展、不撤销其 Notebook 授权，也不删除笔记。已安装包的公开地址仍可用于原有手动更新；撤销发布者信任请使用独立的信任管理入口。

目录客户端支持用户配置的目录及本地清单制作；已安装扩展另可开启 [自动检查更新](EXTENSION-UPDATE-CHECKS.md)。中央市场运营、目录审核评级、私有仓库认证、静默自动安装与通用第三方 React/JS 宿主仍待完成。

## 验收记录（2026-10-03）

最终完整回归 129 项通过，新增目录专项 7 项覆盖设备配置/重启与无自动联网、目录快照与独立信任、所有包元数据绑定、协议与下载边界、刷新/修改/移除/过期后的旧选择拒绝、共享并发与取消，以及命令行生成与输出保护。最终 Linux 打包成功，SDK 离线包通过新增目录类型的严格 TypeScript 消费和运行验证。

生产构建与 Linux 打包应用各通过 14 项编辑器/扩展界面检查、12 次无障碍扫描，自动违规为零。目录场景在真实 Storage utility process 中使用受控 HTTPS 响应，验证保存、刷新、搜索空结果/命中、下载审核、显式信任、独立 Notebook 授权及移除目录后保留安装与授权；没有部署外部目录，也不代表真实公网托管验收。
