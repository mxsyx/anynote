# 桌面流式归档

桌面「导出完整 Notebook」和「导入 Notebook」使用系统保存/打开对话框；渲染器仅提交 Notebook UUID、导出模式（完整/当前）或开放格式（目录/ZIP），不接受文件路径，也不传输归档 base64。导出前显示预计目标磁盘预算，选定文件后后台执行。任务中心显示数据量、预算、进度、完成/失败，并可取消正在处理的任务。导入完成可打开新的 Notebook。

完整 `.anynote` 格式为 ZIP 容器，保存 manifest.json、notebook.sqlite 和该数据库引用的不可变附件文件，包含历史、回收站、批注和扩展状态。设备凭据、目标游标与目录登记不进入包内。同为 schema v4 的内存小包与流式归档可通过两种接口互相导入。

实现使用固定的 [yazl 3.3.1](https://github.com/thejoshwolfe/yazl) 与 [yauzl 3.4.0](https://github.com/thejoshwolfe/yauzl)。导出先在独立 Worker Thread 中只读校验 SQLite 快照的 schema、身份、完整性、外键、目录结构和全部快照引用的附件（包括历史与回收站），完整模式不修改快照身份或索引。通过后才按流计算整库 SHA-256，并在实际打包时复查大小与哈希；失败或取消不发布新归档，也不覆盖已有目标。ZIP64 在文件大小、目录偏移或条目数量越过经典 ZIP 限制时自动启用。流缓冲按 64KiB 读取，附件通过有界缓冲流式校验，不把整个附件或归档读入内存。

## 预算与提交

- 完整解压数据最多 20GiB、100002 个条目（manifest.json、notebook.sqlite 及最多 100000 个附件），manifest 最多 16MiB。容器额外允许压缩及 ZIP 结构开销。最多同时运行两个归档任务。
- 导出估算包括未压缩数据、压缩余量、清单和 ZIP 条目结构；应用数据盘还要有数据库快照空间。预估为保守预算，磁盘空间检查不等于空间预留。
- 导入在数据盘预算解压数据及额外两个数据库大小，用于迁移前快照、事务日志和索引更新。解压前核对清单、条目总量与可用空间。
- 导出在目标同目录创建随机 `.partial` 文件，成功后 fsync，再发布最终名称；失败和取消删除临时文件。覆盖已选择的普通文件前检查 inode、大小和修改时间，发现变化则拒绝覆盖。新目标使用同目录硬链接发布以避免覆盖并发出现的文件；目标文件系统不支持硬链接时任务失败。
- 导入逐文件解压到应用 `_local/archive-jobs/` 临时目录。拒绝路径逃逸、反斜线、重复/大小写冲突、符号链接、加密条目、不支持的压缩方式、未声明文件、大小欺骗和哈希不匹配。
- 导入的 SQLite schema、完整性、外键、资源文件及引用闭包和目录结构检查，以及身份重映射与索引重建，在独立 Worker Thread 中执行；不执行包内代码。完成后才在存储队列里将目录原子发布为新 Notebook，重写包内自指链接。导出和导入取消校验都会等线程退出后清理目录；导入发布阶段不提供取消。

应用异常退出可能留下目标盘上的显式 `.partial` 文件，但不会将其作为完成归档或已登记 Notebook。应用 `_local/archive-jobs/` 暂存目录由任务租约恢复机制回收；目标盘残留需手工清理，当前没有断点续传。

## 仅当前内容

设置中的「导出仅当前内容」仍生成 schema v4 的 `.anynote`，默认「导出完整 Notebook」保持完整归档语义。`currentOnly` 只用于桌面导出任务，不修改源 Notebook。先通过 SQLite backup 捕获专用数据库，再在可终止 Worker 中裁剪：

- 移除回收站及其后代、非 head 修订、已删除批注和无主记录；保留当前标题、标签、收藏、目录、head 修订、有效批注、当前索引/导入报告及 head 的资源引用（含原始 HTML、白板间接图片）。
- 资源表仅保留 head/主资源需要的 ID，以 head 固定的资源版本替换不再需要的当前资源版本；保留所有剩余修订、批注和文本索引引用的资产，重新计算完整闭包后才固定附件文件。
- 删除 changes、扩展独立状态与非 head 的修订元数据，重建当前搜索文本；`secure_delete` 和 `VACUUM` 清除旧记录、FTS 残留及空闲页。未知扩展块原文保留；无法判断的扩展库级状态不属于“当前内容”。
- 清单明确 `includesHistory:false`、`includesTrash:false`、`includesExtensionState:false`；完整模式均为 true。`requiredExtensions.blocks` 记录实际保留块的 `type/version`，`requiredExtensions.data` 记录保留数据的命名空间和 `schemaVersion`。这些是内容格式要求，不是已安装扩展包的 SemVer；不携带或执行扩展程序。

导出数据库校验、身份、引用闭包和 SHA-256 检查仍执行。导入创建新 Notebook；当前模式有且仅有每篇当前 head，不提供已剔除的历史恢复。

## 开放 Markdown 目录 / ZIP

设置提供「导出 Markdown ZIP」和「导出 Markdown 文件夹」。桌面系统对话框授权目的位置，后台任务复用归档的并发上限、进度、取消与临时租约。只处理当前快照；转换在 Worker 中执行，按笔记读取正文，附件以 48–64 KiB 块读写，白板嵌图的 base64 也按块编码。保留目录/资源元数据与单篇正文/场景 JSON；不会将整个附件或 ZIP 放入内存。单份白板场景 JSON 上限 50 MiB。

ZIP 路径先在应用暂存目录生成文件，再通过同一 ZIP64 写入器流式打包；需要快照、跨卷附件副本、转换文件和目的 ZIP 空间。目录路径在用户选定目录下创建独立新文件夹，先在相邻随机 `.partial` 中生成并同步文件，再独占预留最终名称、重命名发布；不合并或覆盖已有文件夹。取消等待 Worker 退出后删除暂存内容。源数据预算仅是初步估算：白板嵌图和重复引用会放大输出，转换中仍逐块执行 20 GiB 总量与 100002 个显式条目上限，ZIP 发布前再次检查实际输出预算；磁盘空间检查不等于预留。

- 名称采用 NFC、过滤非法字符、Windows 设备名保护、UTF-8 标题字节截断和完整 UUID 后缀，避免截断、大小写和同名碰撞。
- 导出相对路径超过 220 UTF-8 字节时映射到 `_long`。`EXPORT-MAP.json` 记录原目录关系、标题、导出路径和按笔记/修订的资源映射；内部链接按最终路径重写并转义空格、括号等字符，保留锚点。外部 Notebook 或未导出目标链接保留并报告。
- 图片/PDF 原件按固定资源版本复制；有效批注写为 `.annotations.json`，其 `target_asset_hash` 对应 `_assets` 原件。
- 白板同时保留预览、原场景 `.scene.json`、图片原件和带内嵌图片的 `.excalidraw.json`；场景文件按 head 区分，避免同一场景引用不同图片版本时覆盖。
- `EXPORT-REPORT.txt` 报告历史、回收站、标签/收藏、图片显示尺寸、扩展状态/编辑能力的损失；未知扩展块保留原文并列出 type/version，不能保证其他 Markdown 阅读器渲染。开放导出不是完整恢复容器。

绝对路径仍受目标操作系统和文件系统限制；深目录合成回归不等于 Windows 长路径或跨平台真实磁盘验收。浏览器 `exportMarkdown` 保留 100 MiB 内存 ZIP 入口，不提供新的流式任务。

## 入口预算

共享定义位于 `packages/protocol/src/import-limits.ts`，设置、网页导入与跨库转移界面显示实际入口限制。所有 MiB/GiB 均为二进制单位。

| 入口                                                 | 当前预算                                                                                                                           |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 普通单文件导入                                       | 50 MiB                                                                                                                             |
| 浏览器/旧 base64 归档、本地快照、浏览器开放 Markdown | 100 MiB；旧归档导入还限制 10000 个条目                                                                                             |
| 跨库转移                                             | 10000 个条目；结构记录和附件各 100 MiB，仍为内存路径                                                                               |
| 桌面流式完整/当前归档                                | 20 GiB 解压总量、100002 条目，清单最多 16 MiB                                                                                      |
| 桌面流式开放导出                                     | 20 GiB 转换后输出、100002 显式条目；快照闭包仍受附件数量/大小预算约束                                                              |
| 网页/HTML                                            | HTML 10 MiB、单资源/响应 20 MiB、资源总量 80 MiB（含保留 HTML）、200 项、4 路并发、每响应 30 秒、图片解码 40 MP × 4 字节；只能调低 |
| 正式云备份/恢复                                      | 独立 20 GiB 文件分块路径，见 [流式云备份](STREAMING-CLOUD-BACKUP.md)                                                               |

20 GiB 不是所有导入、转移和快照入口的统一上限。本组只新增当前归档与桌面开放导出路径，没有扩大其他入口。
