## 关键边界

- A007 负责 Cloudflare 与通用远端故障、长期调度，以及 endpoint 条件写、发布冲突与响应丢失确认；原 A004 中的 Cloudflare 验收范围转入本项。
- Cloudflare 组按故障、老化复验、容量分阶段接续；超过 24h 和连续 7 天的真实等待跨会话保留样本。共享命名空间不得边清理边做负载；独立命名空间和预算就绪后才可并行。
- 所有组均可先整理已有实现、脚本、场景和报告模板，发现必要修复时补齐相关回归；真实验收须等待对应外部资源。不得把本地模拟、受控时钟或静态 CI 配置写成真实通过。
- 如果验收引出代码修改，先确认共享文件与测试边界；CI/打包脚本的修改安排串行。需要并行开发时使用独立 worktree，公共文档统一收尾。

## 执行建议

1. 准备 Cloudflare 部署与老化样本，同时启动具备资源的公网端点和签名身份验收。Cloudflare 老化等待期间可执行隔离的故障或容量批次。
2. A011 凭据准备与 F006 本地实现分别先行；两者就绪后执行真实 CI 验收，再交给 V011 做最终安装、升级和回退验证。

- **资源门槛**：Cloudflare 部署/样本准备解锁 A007–A009；开发者身份与 F006 共同解锁真实发行验收。不存在阻塞所有组的统一外部前置。
- **需要人工参与的操作**：账号所有者登录与授权、开发者身份/证书申请，以及真实设备的提供与操作；已授权工具可以承担脚本、配置和记录工作。
- **每个会话结束前**：更新所属分组文档的完成复选框、阻塞和下一步，并链接实际证据；部分完成保持未勾选。入口不复制状态。完成后按[文档维护](../DOCUMENTATION.md)归档并移出待办，同步数量、依赖和引用；等待老化的任务额外记录样本标识、创建时间、最早复验时间和保护范围。
