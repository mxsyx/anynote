## 任务

### F006 · 签名与更新逻辑

- [ ] **P1 — 签名与更新逻辑**：接入打包签名/公证流程、安装包与更新签名验证、升级失败回退及不支持的 schema 版本拒绝。现有 GitHub Release/校验和流程不等于签名更新；本地实现和回归可以先行，真实签名/公证依赖 [A011](02-5-release-credentials.md#a011)，最终发行验证归 [V011](01-platform-validation.md#v011)。

## 执行顺序与验收

| 阶段              | 工作                                                                      | 前置与完成边界                                                                                       |
| ----------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 1：契约与本地验证 | 明确产物身份、更新验证、失败回退及 schema 拒绝边界，准备可复现测试输入    | 可先行；测试签名与模拟失败不能记作真实发行证据                                                       |
| 2：实现与回归     | 接入打包签名/公证，完成安装包与更新验证、升级失败回退及不支持 schema 拒绝 | 使用阶段 1 契约，代码、相关回归与发行说明一起完成                                                    |
| 3：真实身份与 CI  | 使用 A011 的有效身份执行真实签名、公证和更新身份验证                      | 依赖阶段 2 与可用凭据；证据及状态归 [A011](02-5-release-credentials.md#a011)                         |
| 4：最终包验收     | 安装、升级、回退和首发平台/架构验证                                       | 交给 [V010](01-platform-validation.md#v010)/[V011](01-platform-validation.md#v011)，结论供 F008 汇总 |

## 代码与验证入口

- [桌面打包](../../scripts/package-desktop.mjs)、[发行 workflow](../../.github/workflows/release.yml)、[发行矩阵](../RELEASE-MATRIX.md)、[凭据规范](../RELEASE-CREDENTIALS.md)。
- 现有 `tests/release-matrix.test.mjs`、`tests/release-credentials.test.mjs` 和 `pnpm run test:release:matrix` 可作为回归入口；需补充签名篡改、非法更新、失败回退和 schema 拒绝的行为验证，现有测试通过不代表 F006 完成。

完成与交接遵循[统一规则](03-feature-logic.md#handoff)。阶段完成不等于整项完成；未满足完整验收条件时保留未勾选。
