## 关键边界

- F001/F002 同改卷接口和本地备份测试，按接口 → Windows 适配 → 物理设备映射/UI 顺序推进；实机分别交给 V009、V008。
- F005 跨多个接口区域，与同包功能改造错开；只改成 unknown 不等于完成调用点校验，也不需要重做已完成的包循环/服务装配治理。
- F006 与 A011 不互相等待启动：实现与凭据分别准备，就绪后汇合验证，再交给 V010/V011。
- 可选能力先确定契约；F013/F014 对齐授权与提案后分别实施，F015 依赖 F014 工具契约。F020/F022 等大项必须继续拆会话。

## 执行建议

1. 启动范围与发布组：先整理 F007 决策材料和 F008 已有证据，同时推进卷与设备组、签名与更新组。
2. F005 选择与当前功能开发无冲突的接口批次；公共类型、CI、打包脚本及证据表修改安排串行。并行开发使用独立 worktree，合入时仍需处理共享契约与回归。
3. 本地实现完成后，按资源就绪情况交给 A/V 类执行真实验收；不因等待证书或设备停住独立实现。
4. 可选能力按产品确认逐项启动，使用路线图中的会话边界和依赖；不批量纳入首发。

## 完成与交接

完成条件：实现、运行时校验、相关回归和文档同步完成；性能优化有前后数据。代码实现与真实账号/设备验收分别结项，不能以“评估完成”代替“功能完成”。

- **门槛组**：范围与发布组的 F007 影响后续范围最广；卷与设备组解锁 V008/V009 的相关验收，签名与更新组和 A011 共同解锁真实发行验证。不存在阻塞所有本地实现的统一门槛。
- **需要人工参与**：产品负责人确认范围；有权限的账号所有者申请开发者身份、授权和配置 CI 凭据；提供并操作真实设备。AI 可整理决策材料、实现逻辑、运行获授权的验证和记录证据。
- **每个会话结束前**：更新所属分组文件的完成复选框、已完成阶段、阻塞和下一步，并链接实际证据；部分完成保持未勾选。以该文件作为跨会话交接的单一来源，入口不复制状态。按[文档维护](../DOCUMENTATION.md)归档完成项，同步数量、依赖、导航锚点与引用；总入口和共享证据表统一收尾。
