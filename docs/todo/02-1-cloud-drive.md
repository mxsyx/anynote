## 执行边界

- 资源：Google Drive、Dropbox、OneDrive 的开发/生产 OAuth 应用身份、测试账号、可撤销授权、配额/限流条件，以及无原机 file ID 缓存的干净第二设备。
- 顺序：按厂商完成 A001 的可用授权 → A002 上传下载闭环 → A003 第二设备恢复，再执行 A004 条件发布与 A005 故障演练。某厂商可用后即可开展对应验收，不等待其他厂商审核；A001 整项结项仍需满足全部要求。
- 同一账号/远端槽中的发布、撤销授权和清理串行；不同厂商使用独立账号、槽和报告时可分批推进。五项共享授权与备份样本，保留在同一组，避免重复准备。
- A004 是各 Provider/endpoint 条件写能力的唯一状态入口；Cloudflare endpoint 的结果由 [Cloudflare 组](02-3-cloudflare.md) 提供并在这里汇总，未测目标不得标为通过。A005 维护云盘故障证据，A007 维护 Cloudflare 及通用远端调度证据，同一报告可引用，任务不重复建项。
- OneDrive 企业/学校租户需额外管理员资源，独立见 [组织租户组](02-2-organization-tenant.md)。已有 Provider、身份注入与本地回归不重复开发；新发现的修复先明确受影响代码和回归范围，未完成的跨进程续传仍归 [F003](03-feature-logic.md#f003)。

## 任务

<a id="a001"></a>

### A001 · 官方 OAuth 应用注册与真实授权

- [ ] **P0 — 官方 OAuth 应用注册与真实授权**：为 Google Drive、Dropbox、OneDrive 准备开发/生产应用身份，配置授权页、隐私政策、回调及必要审核。在真实桌面验证系统浏览器唤起、回环回调、state/PKCE、超时与端口占用、撤销和重新授权。身份注入、错误提示和本地回归已有实现，本条仅保留厂商注册/审核及真实授权验收。步骤见 [OAuth 注册](../OAUTH-REGISTRATION.md)。

<a id="a002"></a>

### A002 · Google Drive 真实端到端验收

- [ ] **P0 — Google Drive 真实端到端验收**：以真实账号验证 `drive.file` 最小权限下的目录创建/发现/上传/下载/删除、resumable 上传（256KiB 分片、服务端确认偏移、会话失效重建）、上传后下载校验、配额与 403 reason 分类、`current` 读回确认。当前 `googleapis` 调用路径与上传下载协议未经过真实 API 验证。

同批补齐 Dropbox App Folder 与 OneDrive AppFolder 最小权限下的真实创建、列表、上传、下载、删除及分段上传闭环；三个 Provider 的实现均已有记录，不重复开发。

<a id="a003"></a>

### A003 · 第二设备只读恢复

- [ ] **P0 — 第二设备只读恢复**：在干净设备（新授权环境、无原机 file ID 缓存）从云盘恢复当前副本，核对条目数、资源哈希、历史、回收站与搜索重建；同时验证 `drive.file` 下发现既有备份并下载的闭环能力。

<a id="a004"></a>

### A004 · 条件发布能力实测

- [ ] **P1 — 条件发布能力实测**：实测各 Provider 与 endpoint 的版本 token/条件写行为；仅在实测通过后才把 `conditionalHead` 置为 true，否则继续使用单写设备槽 + 发布前后检查，并明确不宣称跨客户端原子互斥。

<a id="a005"></a>

### A005 · 真实容量与故障演练

- [ ] **P2 — 真实容量与故障演练**：在真实账号验证空间不足、429/`Retry-After`、授权撤销、token 轮换、上传中断与清理失败重试，记录报告。真实远端故障的通用条目见 [A007](02-3-cloudflare.md#a007)。
