# 首发范围与发布证据

[返回功能任务入口](03-feature-logic.md) · [返回总入口](../../TODO.md)

更新：2026-10-25。

F007、F008 共享首发范围和发布证据表，合为统筹组。AI 可先整理选项、现有证据和缺口；首发取舍由产品负责人决定，最终发布结论需等待范围内验证完成。

## 任务

<a id="f007"></a>

### F007 · 确认首发边界

- [ ] **排期决策 — 确认首发边界**：确定 Windows/macOS/Linux 与架构优先级、典型 Notebook/附件规模、富文本首发深度、PDF 批注、加密是否首发要求、自托管/商业托管及发布日期。由产品负责人决定；此条是待决策事项，不代表缺少某段实现。

<a id="f008"></a>

### F008 · 汇总 v1 发布门槛

- [ ] **P0 — 汇总 v1 发布门槛**：建立并维护逐项证据表，记录版本、设备、语料、命令、报告及未执行原因；先整理已有证据，最终按 [F007](03-4-release-scope.md#f007) 确认的首发范围收齐验证结论。Cloudflare 已有历史备份恢复证据，不能据此宣称当前格式或跨平台全部通过。此条是发布统筹，不是新增产品功能。

## 执行顺序与验收

1. 整理 F007 的待决策选项及其设备、账号和实现成本；同步为 F008 建立证据表，已有证据只按其实际版本与环境登记。
2. 产品负责人确认 F007 范围后，明确必需平台/架构、数据规模和功能，标明可选能力中哪些被正式纳入。
3. 按范围关联 F/A/V 编号，逐项记录版本、设备、语料、命令、报告、结果和未执行原因；实现与验收组持续补充事实。
4. 所有范围内门槛均有可核对结论后再判断 F008 是否完成。缺少证据保持未完成，不把历史 Cloudflare 恢复或本地 fixture 视为当前格式全平台通过。

- F007 是影响后续范围最广的决策门槛，但不阻塞已列为当前实现的本地工作；F008 是持续汇总与最终收口任务。
