# 文档与任务维护

## 目录与产物

[文档导航](../README.md) 按三个用途组织长期材料：

- `docs/design/`：架构、功能设计、格式契约及 ADR，回答为什么采用该方案。
- `docs/development/`：供 Agent 接续开发的 TODO、实施摘要、工程规范和可复现验证步骤。任务唯一入口为 [TODO](TODO.md)，已交付内容见 [实施记录](IMPLEMENTATION.md)。
- `docs/features/`：面向未来产品文档、技术文档与官网的功能素材，说明使用方式、接口、权限、预算和限制，不混入单次验证结果。

项目 `tmp/` 是随时可删除的工作目录，不是永久证据库。验证结果、基准测量、截图、临时图集等一律放入其中：报告默认 `tmp/reports/`，截图默认 `tmp/screenshots/`；脚本必须按需创建目录，不能要求旧结果预先存在。删除后按开发文档重跑对应命令。CI 直接从这些路径收集当次结果。

不可丢失的设计决定、已交付范围、已知失败和剩余任务必须先写入长期文档；不以 `tmp/` 中的文件作为 Agent 接续工作的唯一依据，也不为这些可删除文件建立 Markdown 链接。持续老化样本的状态与服务凭据不是临时报告，仍由专用状态目录管理；不得把它们移入可随时清空的 `tmp/`。发布包、编译输出保留各自的 `artifacts/`、`dist/`、`release/` 等构建目录。

新内容优先补充已有专题；不再为一次执行新建长期验收报告。实施记录只留必要的交付摘要、日期和未闭环问题，逐项日志、数值表和截图放到 `tmp/`。临时文件被清理不等于任务完成，也不能把缺失报告当作通过证据。

## 任务收尾

1. 对照当前源码和配置核对功能、路径、格式、命令；旧文档写“未实现”不能证明功能缺失。
2. 设计取舍变化时更新 ADR，并同步 README、IMPLEMENTATION、SDK、迁移和专项说明。历史结果保留日期、协议及环境边界。
3. 记录版本、改动、实际命令/结果、设备/语料、报告路径及未执行项；部分完成保持未完成，只保留剩余范围。真正完成后移出待办，保存必要的实施摘要；临时验证结果放入 `tmp/`。
4. 更新依赖和所有引用链接，校验相对路径与标题/显式锚点。删除完成条目不重排其他任务编号；不得留下指向已移除任务的链接。
5. 生成目录和未提交报告使用行内代码，给出复现命令。不能把不存在的报告写成仓库内可点击链接。
6. 区分源码核对、本地单元/集成、模拟 RPC 浏览器、真实 API/存储、真实设备和最终发行产物；失败与未执行分别说明。

开发期不要求历史数据兼容；用户确认的扩展状态迁移和不兼容格式拒绝仍是当前功能。未来兼容策略由 [F007 范围决策](TODO.md#f007) 确定。

历史文档核对见 [2026-10-21 报告](history/todo-2026-10-24.md#g18)，旧编号对照见 [2026-10-24 记录](history/todo-2026-10-24.md)，合并前阶段进展见 [2026-10-25 归档](history/todo-progress-2026-10-25.md)。
