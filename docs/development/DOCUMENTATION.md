# 文档与任务维护

## 目录与产物

- `docs/design/`：Rust 和通用架构、功能设计、格式契约及 ADR，只记录设计与取舍。
- `docs/development/`：未完成 TODO、工程规范、接口约束和可复现验证方法。
- `docs/features/`：功能用法、权限、预算与限制，不混入实施过程和单次测试结果。

各分类的 `README.md` 维护相对链接与简要说明。新增、删除或移动文档后同步索引及引用；不保留 Electron 专属的旧方案、取消任务或实施日志。

单次验证结果、基准、截图与临时日志放在 `tmp/`，通常使用 `tmp/reports/`、`tmp/screenshots/`。目录可随时清空，脚本按需重建，不给不存在的临时产物建立 Markdown 链接。持续云老化状态和凭据使用专用状态目录，不能移入 `tmp/`。

## 信息归属

[TODO](TODO.md) 是唯一未完成任务清单，保留剩余范围、阻塞、依赖、必要接续输入与验收条件。部分完成只留下剩余工作；完成或取消的条目移除，不转存实施摘要或历史归档。原编号保持稳定，新增编号不得复用已移除编号。

稳定接口和设计结论更新到既有专题，当前功能用法更新到功能说明；执行历史由版本控制和外部验收证据保存。证据检查器的固定门槛见 [发行范围](../design/RUST-RELEASE-SCOPE.md)，不能因任务从 TODO 移除而取消最终候选证据要求。

## 任务收尾

1. 核对当前源码、配置、接口、路径和命令；不能仅凭旧文档判断实现状态。
2. 更新剩余 TODO 和必要契约，删除已完成或失效的任务与依赖引用，不新增实施记录。
3. 检查所有相对链接、标题/显式锚点和分类索引。已完成任务的引用改到专题契约，不能留下空的完成锚点。
4. 单次验证输出记录版本、命令、设备、语料、结果及未执行原因，存放 `tmp/`；正式发行证据按发行流程保存在受控长期位置。
5. 本地自动化、真实服务、物理设备和最终发行分别验收，不相互替代。活动老化样本先查状态，不能凭到期日期推定通过。

Rust 迁移的数据范围以 [数据契约](../design/RUST-DATA-COMPATIBILITY.md) 为准：保全基线可用数据、配置和用户文件，已知业务内置、未知数据保全，不恢复插件运行机制，也不支持当前本就拒绝的任意历史格式。
