# 文档与任务维护

## 信息归属

| 内容                  | 单一来源                                            | 其他文档如何引用                                                      |
| --------------------- | --------------------------------------------------- | --------------------------------------------------------------------- |
| 任务完成/阻塞、下一步 | `docs/todo/00–21` 中所属 T 条目，后续议题在 BACKLOG | 总入口和专项说明链接到 T 所在文件，不复制复选框                       |
| 已归档任务            | `docs/todo/DONE.md`                                 | 保留 T 编号和证据；从原组移出时同步总入口数量，不保留第二个可维护状态 |
| 设计取舍              | [ADR](adr/README.md)                                | 设计文档链接实际决定；建议和未定产品问题不得写成已实现                |
| 当前行为/格式         | 源码、配置与专项契约文档                            | README 做概要，IMPLEMENTATION 区分当前摘要与历史记录                  |
| 验收证据              | 对应组交接记录中的版本、命令、环境和报告            | 专项验收文档维护步骤和证据，不单独维护同一任务的完成状态              |
| 首发范围与发布汇总    | [G00](todo/00-release-scope.md)                     | 不把实现完成或某项本地测试通过等同于发布通过                          |

本目录没有独立于分组清单的第二套专项 TODO。`P0-BACKUP-READINESS`、`RECOVERY-DRILLS`、性能/云验收文档中的历史结果是证据；未完成事项必须链接所属任务。跨组只引用 T 编号和报告。发现新问题先归入现有范围；确需新增任务时分配唯一 T 编号并更新总入口数量。

## 每组收尾

1. 对照当前源码和配置核对功能、路径、格式、命令；旧文档写“未实现”不能证明功能缺失。
2. 设计取舍变化时更新 ADR；同步 README、IMPLEMENTATION 当前摘要及 SDK/迁移/专项说明。旧统计和历史成功记录保留日期、协议与环境边界，不能当作当前验证。
3. 在所属任务文件记录版本、改动、实际命令与结果、设备/语料、报告路径和未执行项；只勾选满足该条完成条件的任务。共享文档由单一集成人串行回写。
4. 校验相对链接（含标题锚点）、源码和命令入口、格式版本；生成目录/报告用行内代码标注，并给出生成命令。不要把未提交的报告当作仓库内可用链接。
5. 明确证据等级：源码核对、本地单元/集成、模拟 RPC 浏览器、真实 API/存储、真实设备/云服务、最终发行产物。失败与未执行分别写明；命令入口存在不代表命令成功。

开发期不要求历史数据兼容；用户确认的扩展状态迁移和不兼容格式拒绝仍是当前功能。未来兼容策略交 G00 决策，不凭历史文档增加兼容实现或测试。

本次治理的差异、验证与遗留发现见 [G18 核对报告](G18-documentation-review.md)。
