# 文档与任务维护

## 目录与产物

[文档导航](README.md) 是统一阅读入口。`design/` 保存整体设计与存储契约，`adr/` 保存架构决策，`guides/` 保存功能操作与行为说明，`extensions/` 保存扩展开发协议，`development/` 保存开发及发布流程，`validation/` 保存验收步骤与证据边界，`history/` 保存阶段报告和旧任务记录。

新内容优先补充已有专题，避免为同一功能重复建立设计、实施和进度文档。失效说明直接删除或更新；有追溯价值的结果保留日期、版本和环境后归入 `history/`。当前状态以根目录 TODO、源码和专项契约为准，历史报告不作为当前通过结论。

`docs/` 只保存 Markdown。截图及配套图集写入项目 `tmp/screenshots/`，旧 JSON 报告归档到 `tmp/reports/archive/`；这些本地产物被 Git、格式化和 lint 忽略。新验收与基准报告写入 `test-results/`，已有打包产物仍使用 `artifacts/`。文档以行内代码注明本地产物路径及生成命令。

## 任务收尾

1. 对照当前源码和配置核对功能、路径、格式、命令；旧文档写“未实现”不能证明功能缺失。
2. 设计取舍变化时更新 ADR，并同步 README、IMPLEMENTATION、SDK、迁移和专项说明。历史结果保留日期、协议及环境边界。
3. 记录版本、改动、实际命令/结果、设备/语料、报告路径及未执行项；部分完成保持未完成，只保留剩余范围。真正完成后移出待办，保存必要的专项报告或历史证据。
4. 更新依赖和所有引用链接，校验相对路径与标题/显式锚点。删除完成条目不重排其他任务编号；不得留下指向已移除任务的链接。
5. 生成目录和未提交报告使用行内代码，给出复现命令。不能把不存在的报告写成仓库内可点击链接。
6. 区分源码核对、本地单元/集成、模拟 RPC 浏览器、真实 API/存储、真实设备和最终发行产物；失败与未执行分别说明。

开发期不要求历史数据兼容；用户确认的扩展状态迁移和不兼容格式拒绝仍是当前功能。未来兼容策略由 [F007 范围决策](../TODO.md#f007) 确定。

历史文档核对见 [2026-10-21 报告](history/todo-2026-10-24.md#g18)，旧编号对照见 [2026-10-24 记录](history/todo-2026-10-24.md)，合并前阶段进展见 [2026-10-25 归档](history/todo-progress-2026-10-25.md)。
