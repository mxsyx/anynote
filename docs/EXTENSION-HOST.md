# 首方扩展宿主

`packages/extension-host` 提供独立进程宿主。桌面通过 Electron `utilityProcess` 启动，浏览器开发服务通过 Node 子进程启动；两者复用同一消息协议和授权代理。扩展不与存储进程共享数据库实例，也不向主编辑器加载 React 代码。

## 使用

进入「扩展 → 首方扩展宿主」，查看来源、版本与权限，点击「授权阅读模板」。授权限定当前 Notebook、本次应用会话；授权时不创建进程。「创建阅读记录」首次执行时激活扩展，创建并打开 Markdown 笔记。授权后的命令也出现在 Ctrl/Cmd+K 命令面板中。

停用撤销 API 和命令，终止对应进程，保留已创建笔记。重新启动应用需要重新授权。Notebook 目录分离与应用退出也撤销对应会话。进程崩溃、激活失败或超时显示故障；重新授权后才能再次激活。

## 信任与接口

只有应用代码中的 `bundledExtensions` 清单能够指定入口文件。清单不来自 Notebook、渲染器输入、下载包或第三方签名包。新增首方模块需要随应用构建和发布，提供 `activate(context)`，注册清单内的命名空间命令，并返回清理函数。

首方模块具有 Node 系统能力。独立进程提供故障隔离，**不构成 Node 文件或网络访问的安全沙箱**。Notebook/权限限制由 SDK 消息代理实施，不能将其解释成对受信 Node 模块的操作系统权限限制。运行进程不继承应用环境中的云凭据，也不接收存储路径或 Secret Store 接口。

SDK 支持笔记读写、资源读写、搜索和扩展命名空间设置。每次消息都经过协议与既有 SDK 参数验证，Notebook、扩展身份及权限由宿主绑定，写入沿用领域服务的版本、operation ID 与审计规则。停用后拒绝新调用并丢弃迟到响应；已经被领域服务接受的写入可能完成，停用不回滚它们。

第三方扩展继续使用已有声明式 UI、QuickJS/WASM 脚本及受控网络代理，不能通过声明 `trusted-first-party` 升级到 Node。第三方任意 React/JS 视图、原生模块安装和中央市场仍属于后续范围。

## 生命周期与预算

- 按命令惰性激活，每个「扩展 + Notebook」使用独立进程；同一会话复用进程。
- 默认最多 4 个存活进程、每进程 8 个等待请求和 8 个并发 SDK 调用，单条 JSON 消息上限 32MB。
- 启动、激活和命令分别受 15 秒超时约束；无限循环被进程终止，不阻塞主编辑器。
- 空闲 5 分钟释放进程，保留本次会话授权，下次命令重新激活。
- 停用立即撤销代理并拒绝等待请求；给予清理钩子 100ms，随后强制终止未退出的进程，SIGTERM 处理器也不能阻止回收。清理钩子不能阻止撤权。
- 旧会话消息、异常协议、未声明命令与重复注册不能修改新会话。

## 验证

```sh
pnpm test
pnpm run test:extension-host
# 在 pnpm run package 之后验证打包路径：
ANYNOTE_EXECUTABLE="$PWD/release/linux-unpacked/anynote" node scripts/extension-host-smoke.mjs
```

专项测试覆盖真实子进程的 Notebook 隔离、越权、激活失败、崩溃、死循环、撤权、迟到清理与授权竞态，以及协议和进程配额。桌面脚本通过真实界面验证授权、惰性激活、创建与打开笔记、命令面板复用、停用和重启撤权，并扫描授权/停用页面的无障碍规则。报告写入 `test-results/extension-host-desktop.json` 或 `extension-host-packaged.json`。
