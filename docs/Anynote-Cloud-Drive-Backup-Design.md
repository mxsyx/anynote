# 云盘分块备份设计

Google Drive、Dropbox、OneDrive 使用相同的核心流程和 `anynote.cloud-backup-manifest` v2，Notebook schema v3。存储及物理分块契约见 [单 SQLite 设计](SQLITE-STORAGE.md)。

核心负责账号授权、凭据、调度、SQLite 一致性捕获、分块只读句柄和恢复验证；官方扩展负责厂商目录/对象 API、上传、内容校验、条件发布及对象删除。扩展无法访问数据库连接、任意路径或全局凭据。

每个 Notebook/设备有独立槽：不可变数据库块按 SHA-256 命名，清单按 commitId 命名，current 指针最后条件更新。计划按唯一块哈希及大小比较，并检查远端对象存在性；重复哈希在有序清单中保留，上传仅执行一次。全部块校验和清单读回完成，核心逐项核对数据库总大小、整库哈希及块顺序后，才允许发布。

Dropbox 用 content_hash、rev；Google Drive 用对象 ID、MD5 或下载校验；OneDrive 用 driveId/itemId、厂商校验或下载 SHA-256。厂商缺少可靠校验时必须下载验证，不能只凭上传完成或长度相等宣称内容可靠。

恢复下载唯一块到宿主临时目录，核心按顺序组装并校验完整数据库，之后执行统一 SQLite 校验、身份重映射和新 Notebook 登记。GC 保留当前清单引用的全部块，以及受保护和宽限期内对象。断开账号只删本机凭据；删除云端设备槽是单独操作。

账号、设备槽、授权和备份状态留在设备目录，数据库只包含知识数据。旧整库对象/附件清单、旧 schema 和旧格式恢复逻辑已删除。真实厂商 API 验收须在新格式下重跑；现有历史报告不代表本实现已经通过生产环境验证。
