# 云盘分块备份设计

Google Drive、Dropbox、OneDrive 使用相同的核心流程和 `anynote.cloud-backup-manifest` v3，Notebook schema v4。存储及物理分块契约见 [存储与备份设计](SQLITE-STORAGE.md)。

核心负责账号授权、凭据、调度、SQLite 一致性捕获、分块只读句柄和恢复验证；官方扩展负责厂商目录/对象 API、上传、内容校验、条件发布及对象删除。扩展无法访问数据库连接、任意路径或全局凭据。

每个 Notebook/设备有独立槽：不可变数据库块和完整附件文件按 SHA-256 命名，清单按 commitId 命名，current 指针最后条件更新。计划按数据库块及附件文件的哈希和大小比较，并检查远端对象存在性；重复哈希在有序清单中保留，上传仅执行一次。全部块和附件校验、清单读回完成，核心逐项核对数据库总大小、整库哈希及块顺序后，才允许发布。

Dropbox 用 content_hash、rev；Google Drive 用对象 ID 和下载 SHA-256；OneDrive 用 driveId/itemId、厂商校验或下载 SHA-256。厂商缺少可用内容校验和时必须下载验证，不能只凭上传完成或长度相等宣称内容可靠。Google 当前实现不把 MD5 当作应用内容校验证据，新上传分块的额外下载量约等于上传量；无变化时只确认指针、清单及对象状态，不重复下载全部内容。

附件独立存储，历史及资源引用保留在数据库中。没有独立的 `verify.downloadAssets=false` 设置。内容校验始终开启，核心在发布前检查每个数据库分块和附件的校验等级。备份卡片、设备槽及任务报告使用清单中最弱的对象证据：厂商内容校验和、下载 SHA-256、仅确认大小；未知证据明确标为未知。指针或清单读回成功不能提升内容的校验等级。任务历史仅保存经过字段白名单筛选的校验及流量摘要。

恢复下载唯一块到宿主临时目录，核心按顺序组装并校验完整数据库，之后执行统一 SQLite 校验、身份重映射和新 Notebook 登记。GC 保留当前清单引用的全部块和附件，以及受保护和宽限期内对象。断开账号只删本机凭据；删除云端设备槽是单独操作。

Provider 协议版本为 2：`prepareRestore` 只读取 current 和清单，核对清单哈希及 Notebook/设备槽/提交身份；核心完成空间检查后，才将该清单交给 `download`。SDK 的 `previewRestore` / RPC `previewCloudRestore` 返回预计下载量、恢复空间预算、本地可用空间和其他恢复任务预算。下载量按唯一数据库块与附件计算，空间沿用本地快照恢复的保守估计 `3 × 数据库大小 + 附件总大小 + 1 MiB`，覆盖临时块、完整数据库组装及校验/索引重建；附件按文件流式下载，大小与 SHA-256 独立核对。

预览不会下载数据库块。启动时重新读取 current、确认预览的 commitId 并重新检查空间；同一文件系统的并发云盘恢复共享进程内预算，空间不足时在下载前失败。预算不是物理磁盘预分配，其他进程仍可能消耗空间。成功、失败及取消均释放预算，失败/取消清理临时目录；HTTP 请求与下载流绑定任务取消信号，单块下载不得超过清单大小。恢复后以核心实际计算的整库 SHA-256 报告校验结果，不沿用备份时较弱的记录。

账号、设备槽、授权和备份状态留在设备目录，数据库只包含知识数据。旧整库对象/附件清单、旧 schema 和旧格式恢复逻辑已删除。真实厂商 API 验收须在新格式下重跑；现有历史报告不代表本实现已经通过生产环境验证。
