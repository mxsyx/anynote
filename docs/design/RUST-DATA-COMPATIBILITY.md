# 数据接管与回退

桌面更换技术时，用户已经能打开的笔记、附件、历史、配置和用户文件必须保全。这里的兼容范围是确定的可用数据基线，不是任意历史格式。

## 保留什么

| 内容                           | 接管原则                                   |
| ------------------------------ | ------------------------------------------ |
| 笔记本、目录、正文、附件和历史 | 保留身份、关系、原内容与文件位置           |
| 归档、采集包和备份             | 保持各自用途和既有可用格式，不混为一种容器 |
| 备份目标、策略与外部目录登记   | 保留原连接与设备关系，离线不等于删除       |
| 外观、导航和阅读位置           | 读取能够确认的偏好，无法转换的值保全并报告 |
| 密码与令牌                     | 只通过安全存储迁移，失败时请求重新提供     |
| 未知扩展内容及用户文件         | 保留原始内容，不执行，也不当作缓存清理     |

文字导出不能代替完整迁移，因为它无法保留所有历史、批注和独立状态。

## 首次接管

1. 找到真实资料位置，检查空间、文件状态和是否仍有旧程序写入。
2. 保全完整原件，包括未被当前笔记引用的附件、未知状态和配置。
3. 在隔离副本上核对正文、历史、附件、关系和格式是否完整。
4. 复核原目录没有变化，并取得独占写入权后，继续使用原来的正式资料位置。
5. 核对备份目标、待完成任务与凭据，再恢复适当的后台任务。

验证用副本不登记为第二份可同时写入的正式笔记本。中断后从已确认步骤继续，不重复创建或覆盖原件；未通过的笔记本保持只读或不可用并说明原因。

首次接管不自动接管云端写入权，也不自动清理旧数据。普通备份可能排除孤立文件，因此不能作为迁移时唯一的保全副本。

## 凭据失败时

旧密码无法安全转换时，保留连接信息和旧密文，暂停远端任务，让用户重新提供凭据。本地资料仍可使用；重新认证不能被称为自动无损迁移。

## 回退

回退先停止新写入并完成已接受的保存。没有新增内容时可恢复切换前设置；已有新内容时，先保全最新资料，再验证旧程序能够读取，不能用旧快照覆盖新笔记。

共享的云端进度不能倒退。界面偏好和凭据也要分别核对；旧程序不能读取最新凭据时，保持任务暂停并提示重新认证。
