# 备份与恢复

备份保存某一时刻可以完整恢复的资料，与多设备同步分开设计。本地编辑不依赖网络，不同设备也不能悄悄覆盖彼此的备份；备份不提供双向同步或自动冲突合并。

## 几种保护方式

| 方式     | 用途                     | 边界                               |
| -------- | ------------------------ | ---------------------------------- |
| 本地保存 | 记录当前工作内容         | 不等于另有一份备份                 |
| 本地快照 | 保留本机可恢复的切点     | 不能抵御原设备或同一磁盘损坏       |
| 磁盘备份 | 在另一个目标保存完整副本 | 只保留当前完整副本                 |
| 云端备份 | 保存可选择恢复的多个版本 | 需要网络、有效连接和明确的保留策略 |
| 完整归档 | 便携地带走一本笔记本     | 是独立文件，后续编辑不会自动更新它 |

## 一次备份怎样完成

先确定一个一致的内容快照，并固定该快照需要的附件；之后的新编辑属于下一次备份。

数据库按小块比较，附件按整个文件比较，只传输新增或缺失内容。每个完成版本都包含完整恢复清单，只依靠所选版本的清单及其列出的内容恢复，无需按顺序重放更早的版本，避免历史变化链中的一环损坏影响后续版本。

上传或复制一部分不算完成。只有所有必要内容都通过校验并发布后，才显示备份成功；失败时原有有效备份仍可恢复。

## 调度与状态

用户可手动备份或启用自动调度。自动任务只在应用运行时处理，并考虑离线、电池、计量网络和大文件策略。没有变化时避免重复传输。

不同目标分别显示结果，例如云端已完成、磁盘待重试。应用退出不保证长任务已经完成，重开后先核对实际进度再继续。

## 恢复与删除

恢复先在独立位置下载、拼装和校验，完成后登记为新的笔记本。缺失、损坏或取消时不登记半成品，也不覆盖现有资料。

保留原云端身份或接续原分支需要明确选择，不能自动夺取另一台设备的写入权。

云端同一分支由明确的设备发布，接管后旧设备失去发布权限，具体规则见[设备与分支](CLOUD-BACKUP.md#设备与分支)。

删除当前笔记不会立刻删除旧备份中的内容。永久清理备份是独立决定，必须保护仍保留的版本和正在进行的恢复。

## 设计取舍

完整恢复清单不等于每次重传全部数据。捕获仍需要完整数据库的临时空间，数据库内部布局大幅变化时也可能增加传输量。
