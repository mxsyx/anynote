# 内置能力与扩展边界

桌面把已知业务直接内置，不再依赖插件安装、启用或脚本执行。移除插件机制不能连带删除用户已经产生的内容。

## 保留的业务

| 业务                       | 应保留的体验                                 |
| -------------------------- | -------------------------------------------- |
| 白板、视频、网页导入和备份 | 从对应功能直接使用，保留原设置与远程播放意愿 |
| 阅读记录与任务模板         | 直接创建阅读笔记或插入模板                   |
| 摘录、思考等内容卡片       | 查看与修改已知字段，保留未知属性             |
| 阅读统计与相关笔记         | 保留统计含义、检索结果和对正文修改的确认     |
| 阅读目标与整理记录         | 保留用户设置、次数和已产生的结果             |
| 公开文本导入               | 仅在用户明确选择来源后读取，并遵守网络授权   |
| 修改提案                   | 保留提出、接受和有条件撤销的规则             |

同名扩展不一定具有相同行为。用户修改过的脚本不能仅凭名称当作已知功能自动替换。

## 未知内容怎样处理

未知内容块保留原文、属性、附件和历史，并提供安全查看、复制、源码编辑或导出。不能只留下一个“无法显示”的提示后丢弃原数据。

未知程序、设置和状态保全为离线资料，但不再安装或执行。若某项用户工作流必须继续使用，需要先明确业务规则，再提供内置替代；仅能导出旧内容不等于功能已经替代。

## 明确移除的范围

不保留插件安装与更新、动态命令注册、通用脚本执行和插件专用授权体系。未知数据的保全不构成重新开放这些能力的理由。

完成判断同时看内容与使用行为：资料可读、原有可用操作有对应入口，并且设置、历史和恢复没有丢失。具体核对范围见[功能验收清单](../development/RUST-MIGRATION-INVENTORY.md)。
