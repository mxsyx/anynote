# 发行原则

发行判断关注用户能否完整、安全地使用产品。设计目标、编译成功或局部测试通过，都不能单独代表可以交付。

## 必须守住的边界

- 既有可用业务有对应入口；文字编辑、白板和媒体不能默认降为只读预览。
- 现有资料、历史、附件、配置和用户文件能够完整接管，回退保留切换后的新内容。
- 浏览器扩展与云端继续互通，备份、恢复和采集状态准确。
- 声明支持的平台分别完成真实输入、无障碍、媒体、凭据和安装验证。
- 性能与资源占用在代表性资料和设备上测量，长任务不会让核心编辑失去响应。
- 物理磁盘故障、独立设备恢复和真实云服务分别取得证据，不能由模拟结果代替。

未知关键业务没有替代、资料只能导出却不能继续使用、实际平台没有验证时，应明确保留限制，不宣称完整交付。

## 范围与证据分开维护

待办只记录剩余工作。某项任务完成并从待办移除后，最终发行候选仍需要相应验证。
