# 插件数据显式清理

日期：2026-10-04。

在扩展页的「插件数据清理」中查看当前 Notebook 的第三方扩展留存数据。卸载仍保留数据；清理是独立的显式操作。

## 使用步骤

1. 删除迁移副本：勾选备份，点击「预览删除所选备份」。扩展仍安装时也可操作；当前设置、状态和其他副本保留。
2. 清理完整命名空间：先卸载扩展，再点击「预览清理全部留存数据」。预览包含该扩展的设置、状态、启用覆盖、迁移副本及执行回执。
3. 核对记录数、字节数和键名，输入完整扩展 ID，再点击「确认永久清理」。取消预览不修改知识数据。

每次提交只处理一个 Notebook 的一个第三方命名空间。首方 `anynote`、`core` 及其前缀受保护；笔记正文、历史、资源、其他扩展和其他 Notebook 保留。重新安装已完整清理的扩展时，其设置和状态重新初始化，正文中的扩展块仍然保留。

## 一致性与权限

这是核心管理入口，不向第三方脚本暴露清理能力。Notebook 所有者可以清理已撤销授权、来源不再受信任的扩展残留，无需重新授予扩展读写权限。

预览使用数据库读取事务，按键顺序流式计算数据摘要，只返回元数据。它绑定 Notebook、扩展、安装摘要、目标记录内容、revision 和 schema_version，有效期 10 分钟，每个 Storage 服务最多 8 份。关闭服务后预览失效。提交时安装变化、目标数据变化、新增记录或过期会拒绝执行并要求重新预览；全量清理再次确认扩展已卸载。

删除、知识变更序号和清理回执在同一事务提交，失败全部回滚。相同请求与 operationId 的重试返回原结果，即使服务已重启；复用 operationId 提交不同请求会拒绝。回执存于受保护的核心命名空间，随完整归档保留，不随第三方数据一起删除。

## 预算与恢复边界

列表最多显示 128 个命名空间，每个命名空间最多列出 32 份迁移副本。单次预览最多 10000 条记录、总量 128MiB、单行 16MiB，键名元数据最多展示前 50 条。超过预算拒绝修改，界面显示错误。统计字节是键与 JSON 的 UTF-8 大小，不代表 SQLite 文件缩小量；清理不会自动执行 VACUUM 或删除资源文件。

删除在当前 Notebook 内不可直接撤回。清理前生成的完整归档、本地快照和云版本仍含原数据，可恢复为独立副本；本功能不清理那些历史备份。清理后生成的完整归档反映已删除记录，并保留核心清理回执。删除所选迁移副本可释放每扩展 32 份副本的预算；不自动删除旧副本。

## 验证

专项测试覆盖只读预览、损坏 JSON 副本删除、安装与授权边界、输入确认、完整清理范围、并发变化、事务回滚、预览过期和预算、幂等重试、重启及归档保真。桌面场景使用独立临时 Notebook，验证取消、错误 ID、备份选择删除、设置保留、卸载留存和完整清理，核对未知块与其他扩展状态。
