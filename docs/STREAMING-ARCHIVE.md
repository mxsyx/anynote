# 桌面流式归档

桌面「导出完整 Notebook」和「导入 Notebook」使用系统保存/打开对话框；渲染器仅提交 Notebook UUID，不接受文件路径，也不传输归档 base64。导出前显示预计目标磁盘预算，选定文件后后台执行。任务中心显示数据量、预算、进度、完成/失败，并可取消正在处理的任务。导入完成可打开新的 Notebook。

完整 `.anynote` 格式仍为 ZIP 容器，保存 manifest、SQLite 一致性快照及所有已登记资源，包含历史、回收站、批注和扩展状态。设备凭据、目标游标与目录登记不进入包内。旧 ZIP 小包可通过新接口导入，小型流式包也可通过旧接口导入。

实现使用固定的 [yazl 3.3.1](https://github.com/thejoshwolfe/yazl) 与 [yauzl 3.4.0](https://github.com/thejoshwolfe/yauzl)。资源按流读取、哈希和压缩；ZIP64 在文件大小、目录偏移或条目数量越过经典 ZIP 限制时自动启用。数据库快照的 SHA-256 先按流计算，资源在实际打包过程中复查大小和 SHA-256。流缓冲按 64KiB 读取，只有清单和有数量预算的目录元数据留在内存，不把整个包读入内存。

## 预算与提交

- 完整解压数据最多 20GiB、100000 个条目，manifest 最多 16MiB。容器额外允许压缩及 ZIP 结构开销。最多同时运行两个归档任务。
- 导出估算包括未压缩数据、压缩余量、清单和 ZIP 条目结构；应用数据盘还要有数据库快照空间。预估为保守预算，磁盘空间检查不等于空间预留。
- 导入在数据盘预算解压数据及额外两个数据库大小，用于迁移前快照、事务日志和索引更新。解压前核对清单、条目总量与可用空间。
- 导出在目标同目录创建随机 `.partial` 文件，成功后 fsync，再发布最终名称；失败和取消删除临时文件。覆盖已选择的普通文件前检查 inode、大小和修改时间，发现变化则拒绝覆盖。新目标使用同目录硬链接发布以避免覆盖并发出现的文件；目标文件系统不支持硬链接时任务失败。
- 导入逐文件解压到应用 `_local/archive-jobs/` 临时目录。拒绝路径逃逸、反斜线、重复/大小写冲突、符号链接、加密条目、不支持的压缩方式、未声明文件、大小欺骗和哈希不匹配。
- SQLite schema、完整性、外键、资源清单和目录结构检查，以及受信迁移/索引重建，在独立 Worker Thread 中执行；不执行包内代码。完成后才在存储队列里将目录原子发布为新 Notebook，重写包内自指链接。取消校验会等线程退出后清理目录；发布阶段不提供取消。

应用异常退出可能留下显式 `.partial` 文件或临时目录，但不会将其作为完成归档或已登记 Notebook。当前没有断点续传或重启自动清理这些残留。

浏览器归档、旧 base64 API和本地快照仍使用 100MB 内存包预算；正式云备份/恢复已使用 [文件分块](./STREAMING-CLOUD-BACKUP.md)；单文件界面导入仍限制 50MB。此改动扩大桌面完整归档，不等于扩大所有导入和备份路径。

## 验证

```sh
pnpm test
pnpm run build
pnpm run test:archive
pnpm run package
ANYNOTE_EXECUTABLE=release/linux-unpacked/anynote pnpm run test:archive
```

9 项后端测试覆盖：强制 ZIP64/旧包兼容、实际 112MiB 不可压缩附件往返、归档期间继续编辑、已有目标保护、取消清理、路径/符号链接/重复条目/清单与哈希拒绝、正确哈希但包含恶意 SQLite 触发器的包拒绝、超过 4GiB 的中央目录偏移、解压大小欺骗，以及取消数据库校验线程。

ZIP64 大偏移测试使用真实文件的稀疏区将中央目录置于 4GiB 之后；它验证 64 位偏移读写，不声称完成 4GiB 真实附件负载或 20GiB 上限验收。

真实 Electron 生产页面和 Linux 打包应用均通过 112MiB 归档导出/导入、任务中心、路径权限、未知块、标签/收藏/历史/回收站和打开导入 Notebook 的界面测试：`test-results/desktop-archive-acceptance.json`（`entry` 字段区分生产页面与 Linux 打包运行）。系统对话框由测试适配器返回临时路径，不自动点击原生 OS 窗口；系统级选择器交互和 Windows/macOS 仍待验证。
