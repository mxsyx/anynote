## 本机可以继续完成

当前环境为 Linux x64。2026-10-04 检查：工作区位于 ext4，`/tmp` 位于 tmpfs；此前桌面验收使用 `/tmp` 临时目录；现已另行完成 ext4 隔离目录验收，保留两种环境的区别。

- [x] **P1 — 扩展崩溃与故障注入覆盖**：新增清理中与协调重试中连续两次真实 SIGKILL、附件流写入与数据库同步阶段 ENOSPC、发布替换阶段 EACCES（有限重试）及原路径被其他根身份占用后的重新接回。验证当前副本可在源离线时恢复、错误卷不会被删除、旧数据库保留以及幂等清理；本地备份回归共 53 项通过。进程崩溃和模拟 I/O 错误不代替断电、真实拔盘或真实磁盘满。
- [x] **P1 — Linux/ext4 实盘验收**：通过 `--base-dir` 指定工作区 ext4 上的隔离目录，`--require-filesystem ext4` 防止跑错环境；九项真实 Electron/Utility Process 验收全部通过，覆盖首次复制、修改后替换、同步流程、完整校验、取消及恢复。报告 `artifacts/local-backup-ext4-acceptance.json` 记录路径、挂载类型和运行时版本，临时数据已清除；同盘目录不能作为两个独立物理设备的验证。
- [x] **P1 — 引擎规模基准与本机测量**：1,000/10,000/100,000 附件及 100MiB/1GiB SQLite 的四组样本全部通过，覆盖首次备份、零变化、少量变更、全量校验、恢复和 1GiB 大附件取消，记录提交耗时、RSS 与事件循环延迟。真实桌面另行测量 2GiB 复制期间的帧间隔与任务查询。结果与环境边界见 [BENCHMARK.md](./BENCHMARK.md)；同盘热缓存结果不代表外接盘或十万附件 UI 性能。
- [ ] **P2 — 根据基准优化**：十万附件零变化检查约 30 秒、Node 事件循环最长停顿约 4.7 秒、阶段采样 RSS 最高约 825MiB。优先优化资源闭包同步扫描、大清单内存与元数据检查，再评估捕获 barrier、共享 I/O 预算和大量 Notebook 检查开销。当前复制缓冲有界、并发可选 1–4、进度节流；大清单仍是内存数组与完整 JSON。优化后需复测耗时、内存、取消响应及数据保护。
- [ ] **P2 — 规模下的桌面响应测量**：在真实 Electron 中分别测量万/十万附件检查、捕获与提交期间的帧间隔、任务查询及取消响应。现有 2GiB 附件复制测量仅约 617ms、34 帧，不能覆盖大清单阶段。
- [ ] **P2 — 卷适配代码与离线契约测试**：补齐 macOS/Windows 卷信息适配的实现、输出解析、错误降级和 fixture 测试，覆盖稳定卷标识、挂载状态、磁盘名称、文件系统类型、网络挂载与 FAT32 限制。开发和离线解析测试可以在 Linux 完成；真实系统接口与权限行为仍须在下方平台验收中确认。当前 Linux 使用 statfs/mountinfo，macOS/Windows 仅有基础信息。
- [ ] **P2 — 物理设备枚举与提示**：先实现 Linux 的文件系统到物理设备映射、未知/虚拟设备降级和 UI 提示，并为其他平台提供适配接口与 fixture 测试。当前 `stat.dev` 仅识别同一文件系统及任务期间设备变化，不能证明两个分区属于不同物理设备，也不是持久化卷 UUID；缺少两块真实设备时不能验收独立磁盘识别。
- [ ] **P3 — 跨会话免捕获优化**：当前快路径绑定写连接 lineage，应用重启或 LRU 淘汰后首次任务保守捕获；内容相同时仍零内容复制。只有在可靠识别跨会话源替换/分叉后，才可省去这次捕获，并补齐重启、连接淘汰、替换及分叉回归测试。属于进一步优化，当前保守行为可正常备份；新增持久化表或格式迁移仍必须更新版本契约和测试。

推荐顺序：故障注入 → ext4 验收 → 规模测量 → 基于结果优化；平台适配代码可在本机开发，但单独保留平台实测状态。

## 必须在其他平台验证

- [ ] **macOS/APFS**：验证卷适配的真实输出、稳定身份、挂载/重挂载、网络盘与 FAT 限制识别，以及复制、覆盖替换、fsync、校验和完整恢复。
- [ ] **Windows/NTFS**：验证卷与物理设备信息、挂载状态、网络盘与 FAT32 限制识别，以及替换失败、真实文件占用、有限重试、目录同步能力和完整恢复。
- [ ] **各平台 Electron 运行时**：在 macOS/Windows 上验证内嵌 Node 的 SQLite Online Backup、statfs、文件替换与同步行为。Linux 当前版本已通过；不支持目录同步的平台需验证实际降级行为。

## 需要真实设备或人工条件

- [ ] **外接 exFAT 与真实故障**：外接盘执行复制、替换、同步和恢复；大附件复制中拔盘、USB 重连、原挂载点被另一卷占用及真实磁盘满后，验证停止发布/删除、保留旧副本、重接后的提交协调。具备设备后可在 Linux 验证相应部分，无需全部等待其他操作系统。
- [ ] **断电耐久性**：覆盖发布与清理阶段的真实断电及恢复，分别验证各平台/文件系统；SIGKILL 不等于断电。
- [ ] **不同物理设备及性能组合**：验证两个分区属于同一设备、两块独立设备与无法识别设备时的提示；在 SSD→SSD、SSD→HDD、USB 外接盘上记录完整性能样本。当前同盘测试不能代替这些组合。
- [ ] **真实输入法与原生对话框**：人工确认组合输入、保存、目录选择和初始化取消/确认。现有自动化使用派发的组合事件和原生对话框 fixture，不能代替真实系统交互验收。
