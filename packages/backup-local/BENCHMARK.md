# 本地备份 Linux/ext4 基准与验收结果

2026-10-04，设计文档 §16.3 的四组本机规模样本全部通过。首次备份、零变化、少量变更、全量校验、恢复及大文件取消均完成；零变化任务零复制并跳过捕获，恢复数据库哈希一致，取消后原清单和数据库保持不变。

## 环境与数据

- Linux x64，AMD Ryzen 7 H 255，16 个逻辑 CPU，29.17GiB 内存；基准 Node 24.11.1，附件复制并发 2。
- 源、目标与恢复目录位于工作区同一 ext4 文件系统，测试目录为 `artifacts/local-backup-ext4`；未清空操作系统缓存，每阶段单次测量。
- 每个样本包含 1KiB 小附件和 8MiB 合成 PDF：千附件样本包含 1 个 PDF，万及十万附件样本包含 8 个 PDF。数据库由真实历史正文扩展至至少 100MiB 或 1GiB，不使用未知表或空闲页填充。
- 少量变更更新数据库并增加一个资源；十万附件已达到清单上限，改为替换一个资源引用。取消测试流式复制 1GiB 新附件，在实际产生复制进度后请求取消。
- 十万附件样本的前四阶段完成后任务中断，恢复和取消阶段在新进程续跑；原指标保留，新阶段标记 `resumed-process`。不能把两个进程的累计内存峰值视作同一进程。

## 提交、内存与取消

提交耗时与事件循环延迟单位为毫秒；RSS 单位为 MiB。RSS 是每 50ms 采样的各阶段最高值，可能漏掉短暂峰值；原始报告另存操作系统累计进程峰值。取消响应从发送 abort 到引擎返回计算，排除后续旧副本哈希验证；取消前仍需完成检查和捕获。

十万附件零变化检查仍需约 30 秒，事件循环最长停顿约 4.7 秒，采样 RSS 最高约 825MiB。后续需要优化资源闭包的同步扫描、大清单和元数据检查，并测量优化前后的耗时、内存与取消响应。当前结果验证正确性，尚未完成规模性能调优。

## 桌面与故障验收

Linux/ext4 上真实 Electron 41.9.1 / 内嵌 Node 24.17.0 的九项桌面验收全部通过，覆盖授权、首次与增量、组合态保存、删除确认、范围与计划、部分失败、校验明细、恢复导航以及实际复制期间取消。2GiB 附件复制期间观察到 34 帧，观察窗口约 617ms，帧间隔 p95 与最大值均约 18.7ms，任务查询约 7.3ms。这是短窗口复制样本，十万附件检查与捕获期间的桌面响应仍需单独测量。

本地备份 53 项回归通过，包括清理与协调阶段连续两次真实 SIGKILL、附件流与数据库同步的 ENOSPC、数据库发布 EACCES 有限重试、错误根身份保护及重新接回协调。完整回归 35 个测试文件、295 项通过；工作区、类型、lint 与格式检查通过。

原始报告为 `artifacts/local-backup-ext4-benchmark.json` 与 `artifacts/local-backup-ext4-acceptance.json`，运行命令和续跑方法见 [README](./README.md#ext4-与规模基准)。测试临时数据已清理。上述结果仅覆盖本机同盘、热缓存条件；SSD→HDD、USB、冷缓存、macOS/Windows、真实拔盘和断电仍待实测，原生对话框与输入法仍需人工验收。剩余任务见 [TODO](./TODO.md)。
